# Настройки платформы

Переключатели, лимиты и интеграции, которые владелец меняет в админке без релиза:
`/admin/platform-settings`, только ADMIN. Список, значения по умолчанию и правила живут в коде,
значения — в Mongo. Почему так, а не через env — журнал решений, §21
([`../decisions/journal.ru.md`](../decisions/journal.ru.md)).

## Правило

Новая ручка, которая отличается между развёртываниями (продуктовый переключатель, лимит, ключ
интеграции), — это **настройка платформы**, а не новая переменная env. В env остаётся то, без чего
процесс не стартует: база, Redis, ключи шифрования и подписи, домен.

## Как добавить настройку

1. Строка в реестре `config/platform-settings.ts`: ключ, группа, `spec`, `defaultValue`, при
   необходимости `sensitive` и `secret`.
2. Название и пояснение — `platformSettings.items.<ключ>.title` / `.description` в
   `src/lib/i18n/messages/{ru,en}.ts`; новая группа — `platformSettings.groups.<группа>` и тип в
   `src/api/platform-settings/model.ts`.
3. Чтение в коде — `await platformSettingsService.get('<ключ>')`.

Форму в админке писать не нужно: редактор выбирается по `spec`.

| `spec.kind` | Редактор | Проверка на сервере |
|---|---|---|
| `boolean` | чекбокс | только `true` / `false` |
| `int` (`min`, `max`) | число | целое в границах |
| `choice` (`options`) | выпадающий список | одно из значений |
| `text` (`maxLength`, `pattern?`) | строка, у секрета — поле пароля | длина, регулярное выражение для непустого значения |
| `textList` (`maxItems`, `maxLength`) | многострочное поле, строка = элемент | число строк и длина каждой |

Тест `lib/services/platform-settings-rules.test.ts` проверяет, что значение по умолчанию каждой
настройки проходит её же `spec`.

## Как это устроено

- **Чтение** — кэш 60 с в Redis, сбрасывается при записи. Сохранённое значение, которое больше не
  проходит `spec` (правило сузили в новой версии), заменяется значением по умолчанию — продукт не
  падает. Недоступная база — ошибка, а не тихое значение по умолчанию.
- **Секреты** (`secret: true`) шифруются AES-256-GCM подключом, выведенным по HKDF из
  `MFA_ENCRYPTION_KEY` (`lib/security/keys.ts`); новой переменной нет. В админку уходит только
  «задано / не задано», в кэше лежит шифртекст. Смена `MFA_ENCRYPTION_KEY` делает сохранённые
  секреты нечитаемыми — их нужно ввести заново.
- **Чувствительные** (`sensitive: true`) — права, деньги, куда уходят данные: админка просит
  подтверждение.
- **Аудит** — каждое изменение пишет `platform_setting_updated` в журнал безопасности: кто, ключ,
  было → стало (у секрета — только «задан / не задан»).
- **API** — `GET /api/v1/admin/platform-settings`, `PUT /api/v1/admin/platform-settings/<ключ>` с
  телом `{ "value": … }`, `null` — вернуть по умолчанию. Неверное значение — 400 с `code`.
