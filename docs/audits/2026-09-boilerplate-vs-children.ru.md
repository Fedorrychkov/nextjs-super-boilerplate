# Аудит бойлерплейта против боевой практики — сентябрь 2026

Дата: 05.09.2026. Бойлерплейт сравнивался с тем, что уже проверено в продакшене на проектах,
выросших из него и рядом с ним: что там появилось из реальных инцидентов, чего здесь не хватало,
и что осознанно не переносится. Записи решений — `../decisions/journal.ru.md` §1–§9.

**Запись не равна состоянию.** Раздел «Что осталось» — снимок на дату; перед тем как брать пункт,
сверься с кодом.

## Что перенесено

### CI и уведомления

- Уведомления в Telegram о жизни репозитория: открыт PR, запрошено и оставлено ревью, упал CI или
  скан секретов, PR влит — `notify-telegram.yml` + `scripts/telegram/` (чистые функции с тестами
  внутри `pnpm test`, CLI без зависимостей на sparse-checkout). Падения ловятся `workflow_run`,
  а не `if: failure()` в каждой джобе.
- Lighthouse-бюджеты публичных страниц по живому `next start` с пустой Mongo — `lighthouse.yml`,
  `lighthouserc.json`. Вес и CLS ломают, тайминги предупреждают.
- Скан секретов gitleaks по отслеживаемому дереву — `ci-secret-scan.yml`, без paths-фильтра.
- `pnpm gates` (`scripts/gates.mjs`) в матрице `quality`: каждый `scripts/check-*.mjs`, все и всегда.
  Из коробки — размер контракта агента и храповик `eslint-disable` (`scripts/lib/ratchet.mjs`).
- Деплойное уведомление `scripts/notify-telegram.sh` больше не молчит: экранирование трейлера с
  почтой, urlencode тела, проверка ответа Bot API, `TG_DRY_RUN`.
- PR-шаблон.

### Деплой

- `env_public` из Variables репозитория: публичная часть окружения видна и ревьюится; секрет
  остаётся тем, внутри чего есть креденшл. Сетка на секрет, уехавший в Variables; снятие CRLF.
- `doctor_check_enabled`: `pnpm doctor:<env>` по собранному env до того, как что-то тронет сервер.
- Doctor знает топологию sibling-контейнеров: `localhost` внутри api-контейнера, URI без кредов,
  креды без `authSource`, пустые `MONGO_USER`/`MONGO_PASSWORD` — `config/container-topology.ts`.
- `local-containers-run.sh`: хранилища поднимаются и ждутся healthy до api, один бюджет ожидания
  300 с, `docker logs` при падении, отказ `docker pull` останавливает деплой; preflight pull в
  воркфлоу до разборки стека.
- `deploy-utils.sh` терпит CRLF в env-файле; `memory-limits.sh` даёт Grafana 43 % пула метрик и
  предупреждает ниже пика; Grafana пинится на 13.2.1.
- `setup-local.sh` / `make setup` — повторяемый онбординг; `init-project.sh` остаётся одноразовым
  шагом форка.

### Агентский слой

- `CLAUDE.md` — тонкий адаптер с `@AGENTS.md`; `.claude/settings.json` с fail-closed гейтом
  `scripts/guard-external.sh` на `PreToolUse`.
- `AGENTS.md` / `AGENTS_RU.md` — раздел правил: лестница приоритетов, размер работы, «сделано и
  достаточно», тесты, что ловится машинно, дисциплина документации.
- `docs/agents/review.ru.md`, `triage.ru.md`; `docs/decisions/journal.ru.md` (форма записи, `§N`);
  `docs/plans/README.md`.
- `.gitignore` — рантайм агентов (`.claude/*.local.json`, `.mcp.json`, `.playwright-mcp/`, …).

## Что осталось (бэклог, по убыванию ценности)

1. **Heartbeat воркера в БД**: модель `WorkerHeartbeat`, запись раз в интервал из
   `worker-scheduler.ts`, индикатор «воркер жив / молчит N минут» в админском overview. Сейчас
   смерть воркера выглядит как здоровье. Средняя работа.
2. **`SEO_INDEXING_ENABLED`**: стейдж по умолчанию `noindex` + `robots` Disallow, открывается
   флагом. Мелкая работа, до появления стейджа.
3. **Skills-слой для трёх агентов**: `.agents/skills/` как источник, symlink-адаптеры
   `.claude/skills`, `.codex/skills`, `.cursor/skills`, `.mcp.json.example` +
   `.codex/config.toml.example` + скрипт синхронизации, проверка паритета в гейте. Имеющийся
   `skills/NSB_SETUP_SKILL.md` переезжает туда. Ценно, когда команда реально на трёх инструментах.
4. **Security overrides** в `pnpm-workspace.yaml` (`sharp >=0.35`, `postcss >=8.5.18`, `fast-uri`,
   `immutable`, `brace-expansion 1.1.16/5.0.8`, `dompurify >=3.4.12`). Требует `pnpm install` без
   `--frozen-lockfile` и проверки `next/image` после `sharp`.
5. **Ярус `test:db`** (`quality.yml` с `withDb`, `Makefile test-db`): нужен, когда появятся
   гарантии уровня БД (уникальные индексы, транзакции). Пустой ярус заводить вредно — сюита,
   которой нужна инфраструктура, однажды скипнется и будет светить зелёным.
6. **Воркер blue/green и multi-domain** (стоп обоих цветов воркера, `DOMAINS_LIST` /
   `FIRST_DOMAIN_VALUE`, wildcard-сертификаты через DNS-01). Переносить, когда появится продукт с
   поддоменами тенантов.
7. **Stage-деплой**: копия `prod-deploy.yml` с `develop` → stage, когда у демо появится
   стейдж-сервер.
8. **`check-gate-list`**: сверка таблицы «что ловит CI» в `review.ru.md` со списком джобов в обе
   стороны. Полезно, когда гейтов станет больше пяти.

## Что осознанно не переносится

- **Доменные инварианты и их гейты** (один писатель для леджера, запрет ветвления по коду
  провайдера вне адаптеров, проверка DTO наружу) — специфика конкретных продуктов. Общая идея
  «инвариант — это гейт, а не абзац в контракте» перенесена как механика (`gates.mjs`).
- **Cursor-хуки с адаптерами на личные `~/.claude/hooks`** — завязано на локальную машину; здесь
  гейт лежит в репозитории и работает у любого.
- **Grafana на поддомене** — требует wildcard-сертификата; остаётся `/grafana`.
- **Реплика-сет Mongo в compose** — нужен только транзакциям; бойлерплейту достаточно standalone.

## Как проверялось

`pnpm gates`, `pnpm test`, `pnpm typecheck`, `pnpm lint`, `bash -n` по всем правленым скриптам,
бюджет памяти на 4096 МБ, `TG_DRY_RUN=1` с трейлером `<mail>` и кириллицей, гейт на 31 команде
(allow / deny как ожидалось), YAML всех workflow и compose разобран парсером.

Перед коммитом дифф прошёл адверсарное ревью (5 ревьюеров по направлениям — Actions, shell,
node-скрипты, доки, верность переноса — и по три опровергателя на каждую находку): 22
подтверждённых, 1 отклонена. Две P0 — Mongo без healthcheck при Stage 0 (каждый холодный деплой
падал бы через 300 с) — и остальное починены в том же диффе, разбор в `../decisions/journal.ru.md` §8.
Доктор на шаблоне `.env.example` с выключенным LLM — 0 ошибок; с включённым без ключа — 1.

**Не проверялось:** сами workflow на GitHub (нужен push), Lighthouse-пороги на реальном демо
(первый прогон покажет, подгонять по факту), `doctor:prod` на боевом env демо — если он красный,
это находка, флаг выключать осознанно. Демо идёт с `metrics_enabled: false` (см. §7): если у VPS
≥ 4 ГБ, поставь реальный `server_memory_mb` и включи обратно.

## Что сделать при выкатке

- Секреты репозитория `TG_TOKEN`, `TG_CHAT_ID`, `TG_THREAD_ID` уже есть (те же, что у деплоя).
- Variable `WEB_ENV_PUBLIC_PROD` — необязательна; пока пусто, всё едет из секрета `WEB_ENV_PROD`.
- Первый прогон `Lighthouse` — посмотреть сводку и, если бюджеты не сходятся с реальностью
  демо, поправить `lighthouserc.json` тем же днём.
- Следующий деплой пересоздаст Grafana (`latest` → `13.2.1`) — дашборды провижнятся из репо,
  данных не теряется.
