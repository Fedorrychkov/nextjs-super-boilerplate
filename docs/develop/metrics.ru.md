# Метрики: продуктовые события и ошибки

Один фасад для событий и ошибок, приёмник выбирается в админке. Почему так — журнал решений,
§22 ([`../decisions/journal.ru.md`](../decisions/journal.ru.md)). RUM (Web Vitals), просмотры статей
и ИИ-рефералы — отдельные сборщики, этот фасад их не заменяет.

## Куда уходят события

Настройка платформы `metrics.sink` (`/admin/platform-settings`):

| Значение | Что происходит |
|---|---|
| `log` (по умолчанию) | строка в лог сервера на событие; ничего не нужно настраивать |
| `mongo` | коллекция `metricevents` в базе проекта, срок — `metrics.retentionDays` (TTL); сводка в `/admin/metrics` |
| `posthog` | PostHog batch API (`metrics.posthogHost`, секрет `metrics.posthogKey`); IP и гео не уходят никогда |
| `custom` | приёмник, зарегистрированный в коде: `registerMetricsSink({ send })` из `@lib/metrics` |
| `off` | события отбрасываются |

`metrics.errors` — отправлять ли ошибки туда же.

## Что собирается

- **Список событий закрыт** — `METRIC_EVENTS` в `lib/metrics/rules.ts`. Свойства — только значения
  из перечислений: свободный текст до приёмника не доходит. Из браузера принимаются только события
  с `client: true` (сейчас `$pageview`).
- **Серверные события** — `metrics.track('auth:login', { method: 'oauth' }, { userId })`. Уже
  расставлены: вход (пароль, MFA, OAuth), регистрация, публикация статьи (вручную и по расписанию).
- **Ошибки** — неожиданный 500 из обработчика API, окончательный провал задачи воркера, ошибки
  браузера (`window.onerror`, `unhandledrejection`, `src/app/error.tsx`, `global-error.tsx`). Текст
  вычищается (email, JWT, id, query, длинные числа и токены), одна и та же ошибка уходит не чаще раза
  в 5 минут. Неверный id в запросе (mongoose `CastError`) — это 400, а не ошибка сервера.
- **Кто** — вошедший пользователь виден как `u_<hmac>` (HMAC от id с серверным секретом: стабилен, но
  не раскрывает аккаунт), анонимный браузер — `a_<uuid>` из localStorage, сервер без пользователя —
  `server`.
- **Согласие** — просмотры страниц отправляются только с согласием на аналитику (тот же баннер, что
  у RUM). Ошибки — всегда: это отчёт о сбое без содержимого страницы.

## Как добавить событие

1. Строка в `METRIC_EVENTS`: имя, `client`, допустимые значения свойств.
2. `metrics.track(...)` в месте успеха действия. Вызов не ждёт и никогда не бросает: сбой приёмника
   пишется в лог и не ломает действие.

Браузер шлёт пачки на `POST /api/v1/ev/batch` (путь неочевиден, чтобы блокировщики реже его резали):
не больше 32 КБ и 50 событий, свой лимит 60 пачек в минуту на IP, ответ всегда 200.
