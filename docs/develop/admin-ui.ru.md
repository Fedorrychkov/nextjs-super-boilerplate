# Админка: меню, каркас страниц, токены темы

Как устроен кабинет администратора и где менять его облик при форке. Почему так — журнал решений,
§23 ([`../decisions/journal.ru.md`](../decisions/journal.ru.md)).

## Цвета темы — `config/design-tokens.json`

Палитра живёт в одном файле: `light` — значения для `:root`, `dark` — только то, что тёмная тема
переопределяет. `src/app/tokens.css` из него генерируется, руками не правится:

```bash
pnpm tokens
```

`pnpm gates` (`check-design-tokens`) падает, если `tokens.css` разошёлся с источником, если в `dark`
есть имя, которого нет в `light` (в светлой теме переменная осталась бы без значения), или если имя
или значение сломали бы CSS. Tailwind видит токены как раньше: соответствия `--color-*` → `var(--*)`
остаются в `@theme inline` в `globals.css`. Новый токен, которым пишутся классы (`bg-<имя>`), — строка
в JSON плюс строка `--color-<имя>: var(--<имя>)` в `@theme inline`.

При форке под свой бренд обычно хватает `primary`, `ring`, `sidebar-primary`, `brand` и `chart-*`
в обеих темах.

## Меню

`src/components/Layouts/PlatformLayout.tsx` — группы по задачам: «Управление» (обзор, пользователи,
уведомления, настройки платформы), «Контент», «Аналитика», «Безопасность». У пункта только для
администратора — `disabled` для остальных ролей; группа, где роли не осталось ни одного пункта,
не показывается (редактор не видит пустых заголовков). Первая группа сохранила `id: 'admin'`, так
что сохранённое раньше состояние секции не сбрасывается. Как запоминается раскрытие секций —
[`sidebar-navigation.ru.md`](./sidebar-navigation.ru.md).

## Обзор — `/admin`

Первая страница администратора: что требует внимания, состояние базы, Redis, воркера и приёмника
метрик, счётчики людей и статей. Данные собираются на сервере при каждом заходе
(`lib/services/admin-overview.service.ts`); недоступная зависимость показывается, а не роняет
страницу. Что считать тревогой — чистая функция `overviewAlerts` (`lib/services/admin-overview-rules.ts`,
с тестами): выключенный воркер — норма, пока нет отложенных статей; живой воркер при просроченной
публикации — значит, падает сама задача. Редактора `/admin` отправляет к статьям.

## Каркас страницы и базовые элементы

В `src/components/ui`:

| Компонент | Когда |
|---|---|
| `PageShell` | заголовок страницы кабинета, строка «зачем эта страница», действия справа; ширина `narrow` / `default` / `wide` |
| `EmptyState` | пусто или недоступно — с подсказкой и действием, а не голая серая строка |
| `Switch` | настройка-состояние «включено / выключено»; `button role="switch"`, работает с клавиатуры и с `<label htmlFor>` |

Метка поля (`Input`, `Select`) поднимает только первую букву: прежний `capitalize` делал из
«Когда опубликовать» «Когда Опубликовать».

## Поиск человека

`/admin/users` — поле «Поиск по email или id»: часть адреса без учёта регистра или точный id из
лога. На сервере — `q` в `GET /api/v1/user/list` (`lib/db/models/user-search.ts`): текст
экранируется, длина ограничена 100 символами.
