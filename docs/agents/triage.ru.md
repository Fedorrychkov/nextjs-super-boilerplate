# Триаж issues

Задачи живут в GitHub Issues репозитория. Роадмапы в `docs/*_ROADMAP.md` — направление, а не
очередь: пункт роадмапа превращается в issue, когда его берут в работу.

## Метки

| Метка | Смысл |
|---|---|
| `P0` | Ломает пользователей или блокирует дальнейшую работу. Берётся первым |
| `P1` | Ближайшие итерации |
| `P2` | Техдолг, по мере возможности |
| `infra` / `security` / `seo` / `editor` / `agents` | Область, чтобы фильтровать |
| `bug` / `documentation` | Тип, стандартные метки GitHub |

Меток в свежем форке нет — заведи один раз (`gh label create` идемпотентен с `--force`):

```bash
for l in P0:B60205 P1:D93F0B P2:FBCA04 infra:0E8A16 security:B60205 seo:1D76DB editor:5319E7 agents:C2E0C6; do gh label create "${l%%:*}" --color "${l##*:}" --force; done
```

## Что должно быть в issue

1. **Проблема**: что не так и почему, с путями к файлам и номерами строк.
2. **Где**: ссылки на код.
3. **Что сделать**: конкретно.
4. **Готово, когда**: проверяемый критерий, желательно тест.

Issue без «Готово, когда» не берётся в работу: сначала дописать.

## Кто что ставит

- Метки и приоритет — тот, кто заводит issue. Владелец репо может поменять.
- Исполнитель назначается при взятии в работу, ветка называется по номеру: `feat/123-short-name`.
- Закрывается через `Closes #N` в PR. Ветка по умолчанию `main`, поэтому автозакрытие срабатывает
  при merge `develop → main`; до этого issue закрывает автор PR руками после merge в `develop`.
- Уведомление в Telegram о PR (`notify-telegram.yml`) подхватывает `Closes #N` и «см. #M» из тела
  PR — пиши их в теле, не только в заголовке.
